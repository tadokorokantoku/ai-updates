- Claude Fable 5.2（`claude-fable-5-2`）を追加。Fable モデルのデフォルトになった — 1M context、$8/$40 per Mtok、cache read は $0.20/Mtok
- `claude remote-control` に `--settings <file>` を追加。起動するすべてのセッションに settings ファイルを適用する。ファイルが変更された場合、`claude remote-control` を再起動するまで新しいセッションは開始されない
- MCP サーバーがリダイレクトした際に、MCP OAuth リクエストが refresh token などの秘密情報を別のホストへ送信していた問題を修正
- 読み取り専用の Bash コマンドが、権限プロンプトなしで sandbox の外で実行されることがある問題を修正
- Bash の権限チェックがファイル書き込みを誤ったフォルダーで判定し、プロンプトが表示されない問題を修正
- ディレクトリへの `cp` / `mv` が書き込むファイルに対して、deny ルールと protected-file プロンプトが適用されない問題を修正
- プランに Fable が含まれる Enterprise seat で Fable に切り替えた後も「Draws from usage credits」の注記が表示される問題を修正
- 最初のモデルが応答前にブロックされた際、fallback モデルがリクエストを拒否したり、停止した応答に言及したりすることがある問題を修正
- Claude Code が登録したサーバーに再サインインするたびに、`claude mcp login` が SEP-2352 issuer の警告を表示する問題を修正
- ネットワークパス（UNC 共有、WSL フォルダー、`/net` マウント）で、cell を指定しない `NotebookEdit` 呼び出しがノートブックの最初の cell を削除または上書きする問題を修正
- ネットワークパス（UNC 共有、WSL フォルダー、`/net` マウント）で、Edit が複数一致のうち最初のものを変更する、空の `old_string` でファイル全体を置換する、ノートブックをテキストとして編集する問題を修正
- 新規セッションが auto mode で始まる場合に `/config` がデフォルトの権限モードとして Manual を表示する問題を修正。「Auto (default)」で Space を押すと Plan ではなく Don't Ask が保存されるようになった
- Windows: 作業ディレクトリのドライブレターが小文字の場合、最初の shell コマンド以降、`watchPaths` で設定したパスの `FileChanged` hook が停止する問題を修正
- `--plugin-dir .` および `--plugin-dir ./builtin` が、Claude Code 組み込み plugin の生成型ファイルを `builtin` フォルダーに書き込む問題を修正
- 正確な token 数が取得できない場合に、context 使用量の推定が tool 定義を過大にカウントする問題を修正
- Remote Control（web とモバイル）で `/compact` が二重に表示される問題を修正
- plugin の自動更新と `/plugin` marketplace の更新が、リポジトリの worktree やフォルダーごとに plugin を再ダウンロードする問題を修正
- ターンを開始したバックグラウンド subagent のレポートに Claude が応答する前に会話が compact されると、auto mode がそのレポートを失う問題を修正
- `git stash` などでプロジェクトの skills、commands、agents のフォルダーが削除されセッション中に復活した場合（worktree 進入後を含む）、それらが見つからないままになる問題を修正
- `claude -p` が、バックグラウンドコマンドは 30 分与えられると Claude に伝えるが、実際は 10 分で停止される問題を修正
- クラウドセッションで `pkill`、`pgrep`、`pidwait` がセッション自身の親プロセスにマッチする問題を修正
- プロキシが接続を停滞させる環境で、親プロセス終了後も Claude in Chrome と computer use のサーバープロセスが残り続ける問題を修正
- 大きな hook 出力が、同じ tool call 内の別の hook の出力を保持するファイルを Claude に指し示す問題を修正
- Claude Code を組み込んだアプリが、複数の hook が ask した際に別の hook の理由ではなく自身の PreToolUse hook の `ask` 理由を受け取る問題を修正
- 別の hook の `defer` が先に完了して処理できなかった場合に、PreToolUse hook の `ask` が失われる問題を修正
- 権限プロンプトとバックグラウンドタスクで稀に発生するクラッシュを修正
- SDK とデスクトップのセッションで、Claude が worktree に入った後にプロジェクトの skills、commands、agents がメニューから消える問題を修正
- macOS: `~/Applications` にインストールされていても `/desktop` が Claude Desktop 未インストールと表示する問題を修正
- 事前起動されたプロセスで開始する Claude Desktop セッションで、OpenTelemetry の repository 属性（`vcs.*`）が欠落する問題を修正
- ページを読むモデルがテキストを返さなかった場合に、WebFetch が「No response from model」をページ内容として Claude に渡す問題を修正。明確なエラーで失敗するようになった
- 起動中にシステムクロックが巻き戻ると、screen reader mode で起動時のプロンプトが遅延する問題を修正
- ダイアログを閉じた後にコマンドのパネルが戻らず、次の再描画まで画面にパネルもプロンプトもない状態になることがある問題を修正
- デスクトップアプリに同名の MCP サーバーまたは extension がある場合、Claude Desktop の Code タブのセッションで最初のメッセージ後にプロジェクトの MCP サーバーが切断される問題を修正
- 返信の途中で接続が切れた際に、ターンが「API Error: EPROTO: The TLS handshake failed」で終了する問題を修正。2.1.302 以前と同様、部分的な返信は保持されるかリクエストが再試行される
- 大きなファイルから単一行を繰り返し読む長いセッションでメモリ使用量が高くなる問題を修正
- fast mode の提供がレート制限、過負荷、障害のとき、返信が失われる、モデルが切り替わる、数分間リトライされる問題を修正。まず同じモデルの標準速度を試すようになった
- 複数の待機中のバックグラウンド agent レポートがある状態で Claude が停止された後、1 つのリクエストに意図より多くのレポートが含まれる問題を修正
- Claude の作業中に入力すると、Claude Desktop の Code タブのセッションから他のセッションへのメッセージが一時停止のままになる問題を修正
- `--verbose` などのフラグも同じ行にある場合に、`agents` の前に指定した `--permission-mode`、`--dangerously-skip-permissions`、`--model`、`--effort`、`--agent` が `claude agents` で無視される問題を修正
- アプリが sign-in token を一時的に引き渡せなかったために、接続は生きているのにデスクトップアプリで Remote Control が「login expired」でオフと表示される問題を修正
- 「Queue for later」で送信した Remote Control のメッセージが、実行中のターンの途中で Claude に届く問題を修正
- git status が失敗したとき、セッション開始時に Claude へ渡される git status がクリーンと表示される問題を修正。利用不可と表示されるようになった
- セッション開始時に Claude へ渡される git status で、変更が stage されていないのに最初のファイルが staged と表示される問題を修正
- クラウドセッションの connector が非常に長い名前のリソースを列挙するとハングまたは out-of-memory クラッシュする問題を修正
- セッション履歴のアップロード中に接続が完全に閉じても、Remote Control が接続済みと表示される問題を修正
- agent view から会話に戻ると screen reader mode がオフになる問題を修正
- 質問が開いた時点で入力テキストの末尾にあった stray な「y」が、screen reader mode の y/n 質問で yes として扱われる問題を修正
- ホストが許可されているがネットワークプロキシが接続できなかった場合に、クラウドセッションが Claude に「ホストはおそらく許可されていない」と伝える問題を修正
- MCP サーバーの再接続やセッションのディレクトリ変更の際に tool の読み込みが完了していないと、接続済みなのに tool が 0 件と表示されることがある問題を修正
- Claude が複数の Bash コマンドを同時に送り、先のコマンドがフォルダーを変更した場合に、誤ったフォルダーで実行されることがある問題を修正
- プロキシから HTTP 507 を受け取るとクラウドおよび Remote Control セッションから Claude が送るファイルが即座に失敗する問題を修正。アップロードは 1 回再試行される
- transcript の読み込み中にメモリ不足になると、新しいメッセージが保存されず `claude -p`、SDK、VS Code のセッションがハングする問題を修正
- ネットワーク上の何かが接続を受け付けても TLS handshake に応答しない場合に、サインイン、token refresh、ログアウトが無期限に待機する問題を修正
- 名前にテキスト方向や制御文字が隠れているファイルが、Claude アプリで別名で表示される問題を修正。Claude はそのようなファイルの送信を拒否するようになった
- モデルが tool call で応答した後も、subagent の進捗サマリーがリクエストを最後まで実行し続ける問題を修正
- `grep -r foo "$PWD/src"` のような Bash の読み取りが、パスを直接入力した同じコマンドは確認なしで実行できるのに権限を求める問題を修正
- managed MCP サーバーの `oauth.omitResource` など gateway より新しいフィールドが `desktop` 設定にあると Claude apps gateway が起動を拒否する問題を修正。警告を出して処理を続けるようになった
- `.zshrc` が `KSH_OPTION_PRINT` を設定している zsh ユーザーで Bash コマンドの結果が空になる問題を修正
- macOS: 有効な MDM profile の読み取りが遅い場合に起動時に「Unable to read managed policy settings」が表示される問題を修正。読み取りは 1 回再試行され、タイムアウトはタイムアウトとして報告される
- 更新のために何も入力せず再起動した agent view が、別の agent view の保存済み入力テキストを消去する問題を修正
- `UserPromptSubmit` hook が再生された権限応答をブロックすると、再起動後にリモートセッションが応答しない問題を修正。この再生時にはこれらの hook は実行されなくなった
- 入力が終了した際、`claude remote-control` が初回質問で Enter なしに入力された `y` を受け付ける問題を修正
- `code:` ルールのない policy を持つ Claude apps gateway の背後で、Claude Desktop が spend limit の警告を表示しない問題を修正
- 一部の plugin を使うフルスクリーンセッションで、短くなった tool result が画面上端からスクロールアウトするとエラーで終了する問題を修正
- モデルが tool call で応答した際に、prompt suggestion が余分な API リクエストを行う問題を修正
- stdio および HTTP MCP サーバー上の `PreToolUse` `mcp_tool` hook の応答が 16 MiB を超えるとスキップされる問題を修正。tool call は拒否されるようになった
- 一部のフォントで空白に描画される Bamum 文字を含む skill / command 名を拒否するように修正
- Linux で、NFS エクスポートが満杯または NFS quota を使い切って transcript 行が失われた際に、`claude -p` が何も表示せず exit 0 で終了する問題を修正。エラーを出力し、text および json 出力では exit 1 で終了する
- クラウドセッションがサービスによって中断され、誰も Stop を押していないのに、バックグラウンド agent が「ユーザーにより停止」と報告され resume を拒否される問題を修正
- 編集に失敗した場合（権限プロンプトの表示中にノートブックが変更された場合など）でも、NotebookEdit が hook とテレメトリに成功を報告する問題を修正
- 保存された MCP サインイン記録が null の場合に、起動時に画面が真っ白になる・応答がない、`claude mcp list` の出力が空になる問題を修正
- artifact のデータベース collection が大きすぎてソートできない場合に、Artifact tool が Claude にフィルターの追加を促す問題を修正。collection をページ単位で読み、結果をソートするよう伝えるようになった
- Claude の最初の返信前に再起動すると、再起動したクラウドセッションが大きな画像付きメッセージを失う問題を修正
- 再起動したクラウドセッションで、subagent からメイン会話へのメッセージが未回答のままになる問題を修正
- workflow を停止または一時停止しても Claude に通知されなかった問題を修正。workflow がまだ実行中だと言わなくなった
- `/model` picker を改善：「More models」が他のすべての行の下にある番号なしの行になり、古いモデルはその下に開いて、他の番号は振り直されない
- Gateway: 負荷の高い replica での spend limit を改善。チェックのスキップが減り、spend の記録が早くなった
- Claude apps gateway のサインイン上限メッセージ（Claude Code と `/device` ページ）を改善：gateway の設定名を表示しなくなった（gateway 自身のログには引き続き表示される）
- `claude install` とインストールスクリプトを改善：完了が 2〜4 秒速くなった
- プロセスがクラッシュした Remote Control セッションが新しいメッセージを受け取れるようになるまでの時間を改善
- Windows: ヘルパープロセスを起動せずに PATH 上のプログラムを検索することで、起動時と最初のコマンドの時間を改善
- auto mode を改善（headless セッション、デスクトップアプリ、VS Code）：まとめて待機している背景 subagent のレポートに、ターミナルと同様に 1 回のモデル呼び出しで応答する
- `claude --bg --worktree` セッションで worktree をセットアップできなかった場合の agent view の行を改善：内部タグや末尾 200 文字ではなく、エラーを先頭から表示する
- artifact が別の組織にある場合のメッセージを改善：`/login` は自分の組織の場合のみ提案され、アカウント移行後のコピーの場所も Claude が伝える
- 1 つのリクエストに収まらない数の画像があるセッションを改善：Claude は破棄された画像を既に見たかどうかを伝えられ、変更のない画像の繰り返し読み取りは制限される
- `claude remote-control` の未回答の初回質問に対するメッセージを改善：次に何をすべきかを示すようになった
- 信頼する TLS 証明書の読み込みを高速化し、起動時間を改善
- Claude apps gateway のエラーメッセージを改善：ユーザー名やパスワードを含まない gateway のアドレスを表示する
- Claude apps gateway の spend limit エラーを改善：リセット時刻がローカル時間で表示される（例：「resets 4pm (America/Los_Angeles)」）
- Windows: 標準の Git for Windows インストールで、起動のたびにどの git.exe を実行するか確認しないようにして起動時間を改善
- セッションフィードバックのメッセージと `allowedProviders` 設定の説明で Pro、Max に加えて Ultra を明記し、`forceLoginMethod` の説明をすべての有料 Claude プランを対象とするよう更新
- 同梱の dataviz skill を更新：それぞれ独自の上限を持つ複数の比率には、項目ごとに 1 行の meter リストを提案する
- 「Upgrade to Max」オプションを「Upgrade to Max or Ultra」に更新
- Claude が書く mod を、managed の `allowUnsandboxedCommands: false` や `allowManagedDomainsOnly` があっても auto / bypass モードでは確認なしで有効にし、`dontAsk` モードでは読み込まないよう変更
- mod 自身の tool call（`$.tool.call`、`$.mcp.call`）で、自分の ask ルールや `dontAsk`、`-p` 実行でも権限プロンプトを出さないよう変更。deny ルールと組織ポリシーは引き続き適用される
- 保存済みの Fable 5.1 モデル選択を `fable` に移行するよう変更：Pro / Max プランでは即時、Team / Enterprise プランでは組織が許可した時点。戻すには `/model claude-fable-5-1` を使用
- `/fast`、`/config`、`/model` の fast mode ラベルを、現在のモデルが fast mode に対応している場合はそのモデル名を表示するよう変更し、VS Code の行から「(Opus only)」を削除
- ネストされた skill の読み込みを変更：Claude が `~/.claude/plugins` 内のファイルを扱う際、その中の `.claude/skills` フォルダーは読み込まれなくなった
- Self-hosted runner: 不要（セッション終了または一時停止、work order の置き換え）のためサーバーが拒否したオンデマンド runner は、exit 1 ではなく exit 0 で終了するよう変更
- Windows: Claude Code 自身が起動するプログラム（git など）の検索方法を変更：相対パスと UNC の PATH エントリ、およびネットワーク共有へのリンクをスキップし、settings で設定した PATH の変更を反映する
- 非対話セッションの OpenTelemetry hook イベントで、Bash と PowerShell 呼び出しの後に 2 つの組み込み hook を `num_hooks` と `num_success` から除外するよう変更
- `cp` と `mv` をパス指定（`/bin/cp` など）で呼んだ場合も、通常の `cp` / `mv` と同じパスチェックを行うよう変更
- Cowork クラウドセッションを変更：PostToolUse hook は AskUserQuestion の回答や ExitPlanMode の結果のプランを置き換えられなくなり、Claude は元の内容を読む
- 1,000 文字を超えるコマンドのバックグラウンドコマンド通知と TaskStop の結果で、Claude には先頭と末尾のみを表示するよう変更（context を節約）
- artifact のデザインガイダンスで、Inter と Space Grotesk を良いデフォルト書体として扱うよう変更
- アカウントのメールアドレスチェックを変更：メールアドレスを含み User-Agent を指定する shell コマンドのみを確認なしで拒否するようにし、他のコマンドや定期実行がそのプロンプトで止まらなくなった
- Remote Control セッションを変更：開始したフォルダーを維持し、接続済みクライアントがセッションを別のフォルダーへ移せなくなった
- 宣言されていない source からの managed `extraKnownMarketplaces` の乗っ取りを変更：保存済みデータは `cleanupPeriodDays` の間、オプションと secrets は `claude plugin restore-set-aside` まで退避される
- 宣言済みの名前を別の source から追加できず、他所のエントリは非表示になり、宣言された marketplace が掲載する plugin はそこから再インストールされるよう、managed `extraKnownMarketplaces` を変更

- Gateway: Bedrock、Vertex、Foundry の upstream が gateway 環境の `ANTHROPIC_*_BASE_URL` 変数を無視するよう変更。別のエンドポイントを使うには upstream に `base_url` を設定する
- headless セッションで、`.claude/skills` 内の mod をファイル変更時に再読み込みするよう変更。オフにするには `CLAUDE_CODE_PLUGIN_DIR_WATCH=0` を設定

- Claude Desktop の Code タブのセッションが、次の入力を待つ前に他のセッションへ送れるメッセージ数を 10 から 20 に変更
- `claude -p` と SDK セッションの `AskUserQuestion` で、未文書化の `afkTimeoutMs` 入力フィールドを設定したホストの権限回答を拒否するよう変更
- [VSCode] auth token と API key の両方が設定されている場合に、ターミナルの起動時警告と同様の警告をプロンプトボックスの上に表示するよう追加
- [VSCode] plugin の権限リクエストが隠し文字を含む名前を表示する問題を修正：「a plugin」と表示されるようになった
