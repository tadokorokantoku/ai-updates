- `--restricted`（または `CLAUDE_CODE_RESTRICTED=1`）を追加: コマンドやコードを実行する組み込みツールと `WebFetch` を削除（`--tools` で明示的に指定した場合を除く）、ファイルツールを作業ディレクトリ内に限定、`bypassPermissions` を拒否、ユーザー・プロジェクト・ローカルの設定ファイルを無視する
- エージェントの frontmatter に `experimental.cacheTtl`（`"5m"` または `"1h"`）を追加: サブエージェントの TTL 設定が構成されていない場合に使用される、エージェントごとのプロンプトキャッシュ TTL
- `claude self-hosted-runner --client-label <label>`（または `SELF_HOSTED_RUNNER_CLIENT_LABEL`）を追加: ランナーが登録する際のラベルを上書き（デフォルトはホスト名）
- サーバー管理設定の診断機能を追加: 設定の読み込みに失敗した際の起動時警告、および `/doctor` と `/status` に読み込み失敗の理由や取得されなかった理由（Bedrock/Vertex/サードパーティプロバイダー、カスタム `ANTHROPIC_BASE_URL`）を説明する行を追加
- GitHub CLI トークンに `workflow` スコープがない場合に `/web-setup` で警告を追加。非常に大きなリポジトリへのプッシュがこのスコープなしでは拒否される可能性があるため
- AWS Marketplace 経由で請求される Enterprise 組織、セルフサーブ Enterprise、Enterprise トライアル向けに `/usage-credits` を追加。メンバーが管理者によりリクエストの上限を引き上げられるように
- Bedrock、Vertex、Foundry、およびテレメトリが無効な場合でも、同一マシン上のセッション間でのクロスセッションメッセージング（`SendMessage` / `ListAgents`）を追加
- 長時間セッションで約1時間ごとに発生していたプロンプトキャッシュミス（および extended thinking のコンテキスト喪失）を修正。OAuth トークンのリフレッシュ後にツール定義が再レンダリングされることが原因だった
- アカウントが使用量超過（usage overage）に入っている場合に、セッションとその `--resume` の間で `ScheduleWakeup` ツール定義が変化し、再開されたセッションの最初のターンで完全なプロンプトキャッシュミスが発生していた問題を修正
- 30日後に Claude Desktop と Cowork のセッションが消えていた問題を修正: トランスクリプトのクリーンアップが、デスクトップで書き込まれたセッションをアプリ内にある間は保持するように（組織ポリシーが保持期間を管理している場合を除く）。新しい `desktopSessionCleanupPeriodDays` 設定でこの除外期間の上限を設定可能
- セッショントークンの期限が切れている間に別の Claude Code プロセスがトークンリフレッシュのロックを保持していた場合にログイン画面に送られていた問題を修正。リクエストは代わりにリトライ可能なエラーで失敗するように
- Windows: セッションからデタッチした後、またはターミナルタブが win32-input-mode のまま起動された場合に `claude agents` の一覧がキーボード操作に反応しなかった問題を修正
- `ANTHROPIC_API_KEY` や API キーヘルパーが設定されているなど、利用できない環境で `/login` の推奨 Console サインインがサインインURLを表示する前に OAuth エラーで失敗していた問題を修正。API キーサインインにフォールバックするように
- `/model` およびファストモード切り替え通知内のモデル名がコードとしてレンダリングされるように修正。`[1m]` のようなサフィックスがリンクではなくそのまま表示されるように
- `CI` 環境変数が設定されている場合に `claude agents` がワークスペース信頼プロンプトをスキップしていた問題を修正
- PRステータスキャッシュに不正なエントリが含まれている場合に `claude agents` が起動時にクラッシュしていた問題を修正
- マシンの電源が切れていた後、エージェントビューが数週間前のバックグラウンドセッションを復活させていた問題を修正。そのようなセッションは実際の終了時刻で停止済みと表示され、開く際に保存された会話を再開するか確認するように
- 新しいセッションを開始する際に、エージェントビューが古い会話を開いたり、入力途中のプロンプトを失ったりすることがあった問題を修正
- `claude agents`: 別のターミナルで既に再開済みの停止セッションを開いても、その会話に対して2つ目のプロセスが起動しないように修正。行にはターミナルで開いている旨が表示される
- ワークツリーのブランチが（プッシュされていないものの）チェックアウト中のデフォルトブランチ（ローカルの `main` など）に既にマージされている場合に、`claude agents` と `claude rm` がセッションの削除を拒否していた（「has commits that are not pushed anywhere」）問題を修正
- `PermissionRequest` または `PreToolUse` フックが不正な回答を出力した際にバックグラウンドセッションが無言で待機していた問題を修正。`claude agents` の行にフック名とスキーマエラーが表示されるように
- フックが有効な JSON ではない標準出力の `{…}` オブジェクトを無言でプレーンテキストとして扱っていた問題を修正。パースエラーメッセージとともにフックエラーとして報告されるように
- プロジェクトの `.mcp.json` で claude.ai コネクタタイプを宣言しているエントリが、信頼済みの「claude.ai」見出しの下に `/mcp` で表示されていた問題を修正。実際のスコープの下に表示されるように
- `headersHelper` が `Authorization` ヘッダーを提供する MCP サーバーが、401 に対してドキュメント通りにヘルパーを再実行してリトライする代わりに OAuth ディスカバリーに陥っていた問題を修正
- 管理設定のセキュリティ承認ダイアログが必要な場合に、Claude apps ゲートウェイへの `/login` がハングしていた問題を修正
- `apiKeyHelper` のみが認証情報である場合に、ゲートウェイのモデルディスカバリー（`CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY`）が実行されなかった問題を修正
- `claude logs` を実行したターミナルでマウストラッキング、bracketed paste、代替スクリーンが有効なまま残っていた問題を修正
- 長いルールが絵文字の途中で切り詰められた場合に、信頼ダイアログのリポジトリ権限ルール一覧に文字化けが表示されていた問題を修正
- ctrl+c の直後に shift+tab を押した際に、権限モードインジケーターが「Press Ctrl-C again to exit」ヒントの裏に隠れたままになっていた問題を修正
- `/ultrareview` およびローカルでシードされたクラウドセッションが、`prod.env` 形式や `*.tfvars` ファイル、または認証情報ファイルのエディタスワップ・一時・バックアップコピー（例: `key.pem.tmp`、`id_rsa.swo`）への未コミットの編集をアップロードしていた問題を修正。これらは今後マシン上にとどまるように
- CLI がサイレントに再接続した後、接続先デバイスで Remote Control セッションの権限プロンプトや最新メッセージが表示されないことがあった問題を修正
- コンテナのセッション認証情報がまだ読み取り可能でない場合に、クラウドセッションが起動時に失敗することがあった問題を修正
- グローバルフラグやラッパーが挿入したオプションがサブコマンドより前にある場合に、`claude remote-control` が自身のフラグ（例: `--spawn`、`--name`）を拒否していた問題を修正
- 起動時の警告（例: 「N MCP servers need authentication」）がトランスクリプトの他の行より1列右にレンダリングされていた問題を修正
- バックグラウンド化されたワークツリーセッションがチェックアウトを失っていた問題を修正。バックグラウンドセッションは実行中にワークツリーのロックを保持するようになり、クリーンアップや `git worktree remove` がそれに影響しないように
- 他セッションへの @-メンションが、非ラテン文字（例: IME で入力した韓国語）で入力された名前にマッチしなかった問題を修正
- 不正な `crossSessionInbound` の値が無言で無視されていた問題を修正。修正されるまで警告を表示し、クロスセッションメッセージを保留（ユーザー設定の場合）または拒否（管理設定の場合）するように
- 組織で利用できない場合（例: `DISABLE_EXTRA_USAGE_COMMAND` で非表示にされている場合）でも、レート制限・使用量・ファストモードのメッセージが `/usage-credits` の実行を案内していた問題を修正
- [VSCode] セッションが一度も保存されなかった場合に、チャットタブが「No conversation found」で固まっていた問題を修正。代わりに新しい会話を開始するように
- Workflow ツールのプロンプトフットプリントを改善: その説明が約5.7kトークンから約1kトークンに削減され、スクリプト作成のリファレンスはバンドルされた `workflow-authoring` スキルに移動
- プルリクエストに変更がない間は、プロンプトフッターのPRバッジが GitHub のチェック頻度を下げるように改善。プッシュや `gh pr` コマンドを実行すると即座に更新される
- 管理設定を改善: クライアント側タイムアウト、MCP起動モード、ストリームウォッチドッグの環境変数が設定承認プロンプトをトリガーしなくなった
- `/ultrareview <PR#>` を改善: 起動前に、Claude アカウントに接続された GitHub アカウントがリポジトリにアクセスできるかを確認し、クラウドセッション開始後に失敗する代わりに修正方法を説明するように
- クロスセッションメッセージングを改善: デフォルトのディレクトリが使用できない場合、ユーザーごとのプライベートな `/tmp` ディレクトリにフォールバックし、通知と `/status` に修正すべきディレクトリ名を表示
- エージェントビューのディスパッチ入力での shift+enter の動作を変更し、（プロンプトと同様に）改行を挿入するように。ctrl+enter でディスパッチしてアタッチする
- `/loop` を変更: セルフペースの動的モードとプロンプトなしの自律デフォルトが、Bedrock/Vertex/Foundry を含め常に利用可能に
- Anthropic テレメトリのエクスポート失敗のログを `[3P telemetry] OTEL diag error` ではなく `[Anthropic telemetry]` として debug レベルで記録するように変更。ユーザー自身の OTel コレクターの失敗と誤認されないように
- Linux ユーザー名前空間でのクロスセッションメッセージングを変更: マップされていない所有者に対する root 相当の信頼が、正規のシステムディレクトリに限定されるように
- サブエージェントから別セッションへの `SendMessage` を変更: 返信があった場合、それはサブエージェントではなく親セッションの会話に配信される旨が結果に記載されるように
