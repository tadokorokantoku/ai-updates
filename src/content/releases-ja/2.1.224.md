- セルフホスト環境を追加: `claude self-hosted-runner` により、自前のマシンやコンテナを Claude Code の web・mobile・desktop セッションの実行先にできるように（Team・Enterprise プラン）
- `archive` プラグインソースを追加: git や npm を使わず、HTTPS 経由の zip からプラグインをインストール可能に。SHA-256 によるピン留めもオプションで利用可能
- 利用不可なペーストを削除するとコマンドのテキストが変わってしまう場合に、キャンセルして確認するステップを追加
- Bedrock 用に `ANTHROPIC_BEDROCK_REGION_PREFIX` 環境変数を追加。`AWS_REGION` から導出されるものではなく、特定のクロスリージョン推論プロファイルを優先させられるように
- `crossSessionInbound` と `dialogExpiry` の設定を追加: bypassed permissions で実行中のセッションへ送られたクロスセッションメッセージは承認待ちで保持され、それ以外のセッションへのメッセージは自動配信されるように
- サンドボックスの認証情報マスキングオプションを追加: 構造化された env 値向けの `extract` と `onExtractNoMatch`、JWT 対応マスキング向けの `decode: "jwt"` と `maskClaims`、AWS SigV4 再署名向けの `awsPairs`/`sigv4`。これらは `network.tlsTerminate` が必要で、user・managed・`--settings` の設定からのみ有効
- クロスセッション `SendMessage` を追加: Claude Code のセッション同士が、同一マシン内外を問わず相互にメッセージを送れるように。`ListAgents` で発見可能（macOS・Linux）
- 200 文字を超える長いプロジェクトパスが、共有のサニタイズ済みプレフィックス配下で別プロジェクトのセッションディレクトリに解決されてしまう不具合を修正。セッション一覧・rename・fork・delete・`/resume` がプロジェクトをまたがなくなるように
- チームメイトの inbox への書き込みが実際には失敗していたにもかかわらず `SendMessage` が "Message sent" と報告していた不具合を修正。配信失敗は今後エラーとして報告されるように
- 末尾にスラッシュを付けて書かれたサンドボックスファイルシステムの deny エントリ（例: `denyRead: "~/.aws/"`）が、Linux と macOS で気づかれずにバイパスされてしまう不具合を修正
- サンドボックス違反の詳細が Bash ツールの結果に一切表示されない不具合を修正。Claude はどのファイルまたはネットワークアクセスが拒否され、なぜ拒否されたかを把握できるように
- ターン中に接続した MCP ツールが、ツール検索用に遅延登録される際にその名前がモデルに通知されない不具合を修正
- 同じプラグインを複数のプロジェクトにインストールした際に、プラグインのインストール記録が気づかれずに破損する不具合を修正
- 呼び出したり復元したりしたペーストの内容が、ペーストが古くなっていたりプレースホルダー番号が衝突していたりする場合に、誤ったデータを添付したり、気づかれずにテキストを失ったりすることがある不具合を修正
- Wayland での copy-on-select がクリップボードに反映されないことがある不具合を修正。2 つの selection 書き込みが競合しなくなるように
- 長いセッションでフィードバックサーベイのトランスクリプト共有が気づかれずに失敗する不具合を修正。共有に失敗した場合は成功メッセージではなくエラーが表示されるように
- コールドスタート時に古いログイントークンが原因で Remote Control の自動起動が断続的に "Remote credentials fetch failed" で失敗する不具合を修正
- `/clear` などの出力のないコマンドの後に、Remote Control と SDK クライアントが空の "(no content)" メッセージを表示していた不具合を修正
- サーバー側のセッションが期限切れになった後に再作成された Remote Control セッションが、以前のローカル会話履歴を新しいセッションにアップロードしてしまう不具合を修正
- フルスクリーンモードを改善: 圧縮を繰り返しても、直近の区間だけでなく圧縮前の履歴全体をスクロールバックに保持するように
- Remote Control を改善: 接続中の web・mobile クライアントが、無音で一時停止する代わりに圧縮の進捗や圧縮後の境界を確認できるように。`/clear` によるリセットも接続中のクライアントに伝播するように
- Remote Control を改善: 接続失敗時に、8 秒間のトースト通知だけでなく、詳細と再接続用のショートカットを含む恒常的な失敗インジケーターを表示するように
- セッションあたり 200 subagent というスポーン上限を撤廃。長時間実行中のセッションが新しいエージェントの生成を拒否しなくなるように（同時実行数・深さの制限は引き続き適用）
- managed settings を変更: 組織の設定が変わっていない場合、再ログインや組織切り替えの後に承認プロンプトが再表示されなくなるように
- フィードバックサーベイのトランスクリプト共有を変更: 同意した場合、直近のリクエストのモデル設定（`CLAUDE.md` の指示を含むシステムプロンプト、ツール定義、モデルパラメータ）もアップロードされるように。シークレットは従来通りマスクされ、共有サイズが大きすぎる場合はこれらのフィールドから先に除外される
- Bash ツールの説明文を変更: コマンドの出力はモデルには表示されるが、ユーザーには確実には表示されない旨を常に明記するように
- 呼び出したペーストのプレースホルダー番号が、入力欄に反映された際に振り直されるように変更
- Remote Control を変更: 圧縮または `/resume` の後に新しいセッションが発行された場合、古いサーバーセッションを死んだまま一覧に残すのではなく、アーカイブするように
- [VSCode] 接続が失敗したにもかかわらず、拡張機能が Remote Control を接続済みと表示していた不具合を修正
- ユーザーが Remote Control をオフにした後もセッション再開時に気づかれずに再接続してしまう不具合を修正（`--resume`、SDK ホスト、VS Code 拡張機能）
- [VSCode] `remoteControlAtStartup` を明示的に有効化しても、セッションがそれに従わない不具合を修正
