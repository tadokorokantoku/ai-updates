- プロキシがエンドポイントを通過させないなど、組織のポリシーが読み込めなかった理由を示す「Organization policy」の行を `/status` と `claude doctor` に追加
- ファイルに保存される前に Claude がインラインで受け取れるコマンド出力とバックグラウンドタスク出力の量を最大 128K 文字まで引き上げる `bashOutputMaxChars` と `taskOutputMaxChars` 設定を追加
- コマンドラインに渡すには大きすぎるプロンプト向けに、サブエージェントのシステムプロンプトをファイルから読み込む `--append-subagent-system-prompt-file` を追加
- 読み込まれているスキルのうち使われていないものと、それがコンテキストに与えているコストを表示する `/skill-doctor` を追加。不要なスキルを整理できる
- 高速入力やキーリピート時に、入力または貼り付けた文字の順序が入れ替わったり欠落したりすることがあった問題を修正
- 作業ディレクトリが `/net` の automount 上にある場合、`/add-dir <subdirectory>` が誤って「couldn't be resolved」エラーを表示していた問題を修正
- AWS または AWS の認証情報ヘルパーが応答しない場合に Bedrock セットアップウィザードがハングしていた問題を修正(現在は明確なエラーとともにタイムアウトする)。また、TLS を検査するプロキシ配下でモデルチェックが失敗していた問題も修正
- 管理設定が `enabledPlugins` でプラグインを強制的に有効化している場合、claude.ai から同期されたプラグインをクラウドセッションが破棄し、失敗する可能性のあるマーケットプレイスのクローンにフォールバックしていた問題を修正
- プロンプト入力欄でインラインの `[Image #N]` チップの直前の文字を削除できなかった問題を修正
- セッションの再開時に、並列ツール呼び出し周辺のフック出力やその他のコンテキストが失われ、再開後のリクエストが変化していた問題を修正
- 携帯電話、ブラウザ、または claude.ai アプリがターミナルセッションに接続した際、またはターミナルでモードが変更された後に、リモートコントロールが古い権限モードを表示していた問題を修正
- 接続された携帯電話やブラウザからターンを停止した後、またはローカルのスラッシュコマンド(`/clear` など)の後に、リモートコントロールのセッションが動作中のまま(スピナーが固まり Stop ボタンが表示されたまま)になっていた問題を修正
- ターン開始前、最初のプロンプト直後に送られた Stop や割り込みを SDK およびクラウドセッションが無視していた問題を修正。ターンは最後まで実行される代わりに停止するようになった
- `/teleport` で取得したセッションをリモートコントロールがアップロードすると、接続先のセッションで携帯電話や web 上、元のセッションに追加されたように見えていた問題を修正
- ネイティブ Windows 上で、TLS を検査する企業プロキシ配下でリモートコントロールの受信イベントストリームが失敗していた問題を修正
- エフォートが設定由来の場合、リモートコントロールのセッションが claude.ai でデフォルトのエフォートレベルを表示していた問題を修正
- Google の認証情報チェックが遅い場合、認証情報が依然として有効であるにもかかわらず `gcpAuthRefresh` が起動時にブラウザを開いていた問題を修正
- 起動時のコネクタ取得がタイムアウトすると claude.ai のコネクタがセッション全体を通じて欠落したままになっていた問題を修正。CLI はバックグラウンドで再試行するようになった
- バックグラウンドエージェントを再開できず、そのウェイクアップがタイトループで再試行された際に高い CPU 使用率が続いていた問題を修正
- 新しいバージョン向けのフィーチャーフラグが、同じマシン上で動作している古い Claude Code のバージョンに誤って適用されることがあった問題を修正
- 使用量エンドポイントがレート制限されている場合や起動直後に開いた場合に、`/usage` と VS Code の使用量パネルがモデル固有の週間上限の行を欠落させていた問題を修正
- `claude -p --resume <file>` がトランスクリプトに記録された不正なセッション ID を採用していた問題を修正。現在は新しいセッション ID で再開する
- バックグラウンドの workflow やエージェントがまだ実行中であるにもかかわらず、ターミナルの進捗インジケーター(iTerm2、Ghostty、ConEmu)がセッションを完了として表示していた問題を修正
- コンテナが行方向と列方向を切り替えた後、ボックスが誤った高さで描画される稀なレイアウトの不具合を修正
- 信頼されたプロキシが `X-Forwarded-For` にポートを付加する場合の Claude apps gateway のクライアント IP を修正。アクセスリストが設定されている場合、読み取れないエントリは 403 になる
- ターミナル CLI が protobuf を使用している場合でも、Claude apps gateway が OpenTelemetry を JSON としてエクスポートするよう Claude Desktop に指示していたため、protobuf 専用のコレクターが Desktop のデータを拒否していた問題を修正
- artifact の更新を監視しているだけのセッションを Desktop と web が使用中として表示していた問題を修正
- Claude Desktop アプリから実行されたローカルの Cowork セッションで、Claude in Chrome の `file_upload` が「paths: expected array, received undefined」で失敗していた問題を修正
- 別のマシン上のオフラインのリモートコントロールセッションへの `SendMessage` が配信済みとして読み取られていた問題を修正。結果は、そのマシンが再接続するまで配信が保留されていることを示すようになった
- バックグラウンドの Bash コマンドで実行された CLI からのプラグインインストールのヒントを修正: 検出されるようになり、生の `<claude-code-hint>` タグが会話に漏れなくなった
- プロセス内のエージェントチームのチームメイトが、最初のターンのツールとスキルのアナウンスを2ターン目に再送し、リクエストのプレフィックスが変化してプロンプトキャッシュを外していた問題を修正
- Claude Code が認識できる場合、`/model` ピッカーと VS Code のモデルピルが、生の Bedrock、Vertex AI、または LLM ゲートウェイの ID の代わりにモデル名を表示するように改善
- `GOOGLE_APPLICATION_CREDENTIALS` が設定されている場合の Google Vertex AI での起動を改善: API クライアントの作成時に Google Cloud のプロジェクト検出を再実行したり、余分な `gcloud` プロセスを起動したりしなくなった
- ストリーミングのパフォーマンスを改善: 既にレンダリング済みのブロックが更新のたびにレイアウトで再チェックされなくなった
- 危険な `rm` の安全確認プロンプトを改善し、位置パラメータに対する `rm -rf` や、二重引用符で囲まれた `sh -c` スクリプト内の `rm -rf` も検出するようにした

- 管理設定の読み込み時(起動時または `/login` 後)の Claude apps gateway の 403 を変更し、再サインインを勧める代わりに、組織で Claude Code が有効になっていない可能性があることを示すようにした
- 管理設定で `forceLoginMethod: "gateway"` を固定しているマシンが、残っている API キーや claude.ai ログインを無視して `/login` を求めるように変更。Bedrock、Vertex AI、Foundry のセッションには影響しない
- auto モードを変更し、公開のダイアグラムレンダラーの URL にコンテンツを詰め込んだリンクをそのサイトへのアップロードとして扱うようにした。明示的に依頼しない限り自動承認されなくなった
